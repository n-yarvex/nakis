## 1. 通用规则

- **纯 JSON**，一端一个文件（客户端 `client.json`，服务端 `server.json`），不支持注释。
- **不认识的键会直接报错**并拒绝启动：拼错、或使用了已删除的旧字段（预连接、连接复用的开关早已删除），启动时就能发现。
- **没写的键用默认值**，各表里都标了。
- **时间**写成字符串：`"500ms"`、`"5s"`、`"2m"`、`"1h"`；写成数字会报错。
- **超出范围的数字会被自动拉回最近的合法值**（不报错），范围见各字段。
- **时间字段写成 0 或负数**会被换成内置值（不一定等于默认值）：`dial_timeout` → 8 s（服务端 5 s）、`handshake_timeout` → 10 s、`keepalive` → 15 s、`shape_wait` → 20 ms、服务端 `idle_timeout` → 120 s、`shutdown_timeout` → 20 s、客户端 `pool_max_age` → **15 s**（默认值是 45 s）。
- **监听地址**写 `主机:端口`；`:1080` 表示所有网卡；IPv6 写 `[::1]:1080`。
- **UUID**：32 个十六进制字符，横线随意，大小写不限。两端必须相同。它是唯一的凭据（等同密码）。
- 以下三件事**没有开关，永远开着**：**预连接**（热连接池）、**连接复用**、**IPv4/IPv6 双栈交错拨号**。仍保留的布尔值只有 `tls`、`allow_private`、`ech_keys[].retry`。
- **没有任何依赖测速或「判断变慢」的开关**：整形与隧道寿命都是随机的前馈策略（见 `pool_max_uses`、`shape_up` 两项），线路抖动不会让行为发生变化。

## 2. client.json 全部字段

### 2.1 基本

| 字段 | 默认值 | 取值 / 范围 | 含义与影响 |
|---|---|---|---|
| `listen` | `127.0.0.1:1080` | `主机:端口` | 本地 SOCKS5 监听地址。**没有认证**，改成 `0.0.0.0` 等于对整个网络开放一个无密码代理 |
| `server` | **必填** | `主机:端口`，多个用逗号 | 服务端地址。域名会解析出全部 IP（IPv4/IPv6 交错）；有多个地址时，池里没有热隧道会同时赛跑（见 `race_count`），按历史握手延迟排序，谁先握手完成用谁，落选的连接放进池里备用 |
| `uuid` | **必填** | 32 位十六进制 | 共享密钥 |

### 2.2 连接池与复用

| 字段 | 默认值 | 范围 | 含义与影响 |
|---|---|---|---|
| `pool_lo` | `2` | 1–1024 | **始终保持**的热隧道数。越大，新会话越不用等握手，但常驻连接越多、对服务端 `max_conns` 占用越多 |
| `pool_hi` | `32` | `pool_lo`+1 – 4096 | 高负载时热隧道的上限，也是池里最多闲置多少条。程序按命中率在这个数附近自动调节 |
| `pool_max_age` | `45s` | >0 | 闲置隧道超过这个时间被退役。**必须小于服务端 `idle_timeout`**，否则池里会放着已被服务端关掉的连接（客户端会发现并丢弃，但浪费一次探测） |
| `pool_max_uses` | `8` | 0–100，0 = 不限 | 一条隧道最多承载几个会话（硬上限）。**每条隧道实际的寿命是随机的**：会话数在 `[ceil(n/2), n]` 里均匀抽取，同时每条隧道还有一个 8 MiB–256 MiB 之间（对数均匀）的随机字节寿命，先到者先退役。所以不存在固定的「第 N 个会话 / 第 N 字节」边界可供统计。值越小隧道越短命、握手越多；设 0 时只受字节寿命约束 |
| `race_count` | `3` | 2–12 | 池里没有可用隧道时，**同时尝试**的最多地址数（前两个立即开始，之后每个多等 50 ms）。程序会在「慢档 3 / 你的设置 / 快档 10」之间按命中情况自行调节；只有一个服务端地址（一个 IP）时没有影响 |

### 2.3 超时与链路

| 字段 | 默认值 | 含义与影响 |
|---|---|---|
| `dial_timeout` | `8s` | 建立 TCP 连接的超时 |
| `handshake_timeout` | `10s` | TLS 握手以及本地 SOCKS5 握手的超时 |
| `keepalive` | `15s` | TCP 保活间隔，让 NAT / 防火墙记得住池里闲置的隧道。NAT 很激进的网络把它和 `pool_max_age` 一起调短 |
| `congestion` | 空 | TCP 拥塞控制算法名，如 `"bbr"`。**仅 Linux 有效**，需要内核已加载对应模块；失败只打一条警告并继续用系统默认值。其他平台忽略 |
| `log_level` | `info` | `debug` / `info` / `warn` / `error`。`debug` 会记录每个会话的目标地址，平时不建议常开 |

### 2.4 发送调度（小包合并）

| 字段 | 默认值 | 范围 | 含义与影响 |
|---|---|---|---|
| `send_pack` | `20480` | 1024–65533 | 上行方向一个帧的**目标大小**（字节）。合并到这么大就直接发；越大吞吐越好，但每次合并可能多等一会儿 |
| `send_tail` | `512` | 0 – `send_pack`−1 | 离装满只差这么多字节时不再等，直接发 |
| `send_quiet` | `4` | 0–64（毫秒） | 合并等待的**上限**：只要还有新数据紧跟着到来，最多持续合并这么久。空闲时的第一个小包不等、立即发出，所以交互延迟基本不受它影响；以交互为主的流量可以调到 1–2 |

### 2.5 流量整形

| 字段 | 默认值 | 含义与影响 |
|---|---|---|
| `shape_up` | 空（关） | 手动指定**上行前几个包**的大小，最多 8 组 `[最小, 最大]`，要求 `1 ≤ 最小 ≤ 最大 ≤ 16382`。**留空时使用自动随机画像（推荐）**：每个新会话、每个方向独立随机抽取前几个包的大小（下行 2–4 个、上行 3–5 个）（对数均匀，几十字节到几 KB），并用随机填充补到恰好大小；画像会**按目标端口自适应**——目标是常见 TLS 端口（443、465、563、636、853、993、995、5223、8443）时，说明隧道里套着另一层 TLS，会多覆盖 2 个包、并提高大包出现的概率，让内层握手也不容易被辨认。这个自适应只看端口和随机数，不测量任何网络状况。设置 `shape_up` 后上行画像**让位给你的设置**（服务端下行仍用自动画像）：第 *i* 个包会不断合并应用写来的数据，直到至少有 `最小[i]` 字节，然后最多发 `最大[i]` 字节、多出来的留给下一包；**不做任何填充**；第一组的下限不会低于认证 + 请求的长度。前几个包之后恢复正常合并，每个新会话都重新走一遍 |
| `shape_wait` | `20ms` | 仅在设置了 `shape_up` 时有用：一个包凑不够最小值时最多等多久，超时按现有数据发（不填充）。调大更严格，代价是慢热连接多等一会儿 |

### 2.6 TLS / ECH

| 字段 | 默认值 | 含义与影响 |
|---|---|---|
| `tls` | `true` | `false` = 明文 TCP，**必须与服务端一致**。明文没有加密，也没有服务端身份验证；此时 `sni`、`tls_pins`、`ech_config` 都不能设置（会报错） |
| `sni` | 空 | 服务器名。不用 pin 时必填（用来校验证书域名）；用 ECH 时也必填（它是藏在加密握手里的真实名字） |
| `tls_pins` | 空 | 服务端**叶子证书公钥**（SubjectPublicKeyInfo）的 SHA-256，64 位十六进制，可带冒号。设置后用它**代替**系统 CA 校验（不再检查证书有效期、域名、签发链）。可写多个，用于证书轮换 |
| `ech_config` | 空 | ECHConfigList 的 base64。开启后 TLS 最低版本固定为 1.3，并且必须设置 `sni`。客户端**不会**自动采用服务端下发的 retry 配置：配置失配时握手失败，需要手动更新 |

TLS 的校验方式二选一：`tls_pins`（自签证书）或不写 pin 而写 `sni`（CA 签发的证书，按系统根证书和 `sni` 校验）。两者都不写会报错。

## 3. server.json 全部字段

### 3.1 基本

| 字段 | 默认值 | 含义与影响 |
|---|---|---|
| `listen` | `0.0.0.0:8443` | 监听地址。绑定 1024 以下端口需要权限 |
| `uuid` | **必填** | 共享密钥 |
| `log_level` | `info` | `debug` / `info` / `warn` / `error` |

### 3.2 出站（连接目标）

| 字段 | 默认值 | 含义与影响 |
|---|---|---|
| `dns` | 空 | 解析目标域名用的 DNS 服务器，`"1.1.1.1"` 或 `"8.8.8.8:53"`，可写多个（按顺序尝试）；空 = 系统解析器。答案缓存 60 秒，同一域名的并发解析合并，上游挂了会暂时继续使用旧答案 |
| `allow_private` | `false` | 是否允许代理访问**回环、私网、链路本地（含云厂商元数据地址 169.254.169.254）、组播**地址。默认关：即使 uuid 泄露，别人也不能拿你的服务器去戳它所在的内网。设为 `true` 才能代理内网 |
| `dial_timeout` | `5s` | 连接目标的超时 |
| `congestion` | 空 | 作用在服务器连向目标的连接和监听口上，同客户端 |
| `keepalive` | `15s` | TCP 保活间隔 |

目标域名解析出多个地址时，服务端会 IPv4 / IPv6 交错、最多取 4 个、每隔 120 ms 错峰尝试，先连上的获胜。

### 3.3 容量与超时

| 字段 | 默认值 | 范围 | 含义与影响 |
|---|---|---|---|
| `max_conns` | `4096` | 1 – 1048576 | 同时处理的连接数上限（含未完成认证的）。超过的新连接被直接关闭。设太小，探测者占满槽位后真正的用户进不来 |
| `idle_timeout` | `2m` | >0 | 隧道在两个会话之间最多空闲多久；也是新连接发来第一个帧的最长等待时间。调小可更快腾出被慢连接占用的槽位，但要大于客户端 `pool_max_age` |
| `handshake_timeout` | `10s` | >0 | TLS 握手的超时 |
| `shutdown_timeout` | `20s` | >0 | 收到退出信号后，给进行中的会话多长时间收尾，超时强制关闭 |

### 3.4 发送与队列

| 字段 | 默认值 | 范围 | 含义与影响 |
|---|---|---|---|
| `send_pack` | `32768` | 1024–65533 | 下行帧目标大小 |
| `send_tail` | `512` | 0 – `send_pack`−1 | 同客户端 |
| `send_quiet` | `4` | 0–64（毫秒） | 同客户端 |
| `merge_pack` | `20480` | 1024–65534 | 隧道里收到的上行小帧，合并成至多这么大的一次写入再发给目标 |
| `max_queue` | `4194304`（4 MiB） | 64 KiB – 256 MiB | **每个会话**排队等写给目标的字节数上限。超过就暂停读取隧道，TCP 反压使客户端自然变慢。它限定了每个会话的内存占用，小内存服务器可以调低 |

### 3.5 TLS / ECH

| 字段 | 默认值 | 含义与影响 |
|---|---|---|
| `tls` | `true` | `false` = 明文 TCP（必须与客户端一致）。此时不能设置 `ech_keys` |
| `tls_cert`、`tls_key` | 空 | PEM 文件路径，开 TLS 时**必填**。可以是 `nakis cert` 生成的自签证书，也可以是 CA 签发的证书（链放进 `tls_cert`） |
| `ech_keys` | 空 | `{config, key, retry}` 的列表（`config` = 单个 ECHConfig 的 base64，`key` = 32 字节 X25519 私钥的 base64）。可配置多个：**轮换密钥时保留旧的、追加新的**，旧客户端不会掉线。`retry: true` = 把这条配置作为「重试配置」下发给持旧配置的客户端 |

服务端 TLS **最低版本固定为 1.3**，ALPN 只回应 `http/1.1`。

## 4. 分享链接与订阅格式

图形客户端不需要用户手写 JSON：一条链接就是一个节点，一份订阅就是一批节点。服务端脚本会输出它们，`nakis link` / `nakis sub` 可以编码、解码、查看。

### 4.1 设计目标

- **一行就是一个完整节点**：uuid、地址、证书指纹、ECH 配置都在里面，复制粘贴即用。
- **只写和默认值不同的参数**：最常见的链接很短；新增可选参数不会让旧链接失效。
- **宽进严出**：生成端用固定、规范的写法；解析端容忍大小写、有无连字符、有无 base64 填充、两种 base64 字母表。
- **向前兼容**：未知参数一律忽略；只有出现不兼容改动时才提高版本号 `v`。

### 4.2 格式

```
nakis://<uuid>@<host>:<port>?<参数>#<节点名>
```

- `<uuid>`：32 位十六进制，带不带连字符都行。**它就是密码**，链接和订阅都要当机密对待。
- `<host>:<port>`：主服务器；IPv6 要带方括号 `[2001:db8::1]:443`。
- `<节点名>`：UTF-8，百分号编码（空格写 `%20`，不要用 `+`）。可为空。
- 参数是标准的 `key=value&key=value`，`+` 会被解成空格，所以 base64 值用 URL 安全字母表（链接生成端就是这么输出的）。

| 参数 | 默认 | 对应字段 | 含义 |
|---|---|---|---|
| `v` | 1 | — | 链接格式版本；比客户端认识的新 → 整条链接拒绝导入 |
| `tls` | 开 | `tls` | 写 `tls=0` 表示明文（不能和 `pin` / `ech` 同用） |
| `sni` | 空 | `sni` | TLS 服务器名（开 ECH 时是内层真实名字）；TLS 下 `sni` 与 `pin` 至少要有一个，`ech` 必须有 `sni` |
| `pin` | 空 | `tls_pins` | 证书公钥指纹，64 位十六进制，多个用逗号 |
| `ech` | 空 | `ech_config` | ECHConfigList 的 base64（URL 安全、无填充；标准字母表、有填充也接受） |
| `alt` | 空 | `server`（追加） | 额外服务器 `host:port,host:port`，接在主服务器之后组成赛跑候选 |
| `shape` | 空 | `shape_up` | 如 `100-300,400-1200`，至多 8 段 |
| `race` | 3 | `race_count` | 赛跑地址数 |
| `pool` | `2-32` | `pool_lo` / `pool_hi` | 热隧道数范围 |
| `uses` | 8 | `pool_max_uses` | 每条隧道最多会话数 |
| `age` | `45s` | `pool_max_age` | 闲置隧道寿命 |
| `ka` | `15s` | `keepalive` | TCP 保活 |
| `wait` | `20ms` | `shape_wait` | `shape` 的凑包等待 |
| `cc` | 空 | `congestion` | 拥塞控制算法 |
| `pack` / `tail` / `quiet` | 20480 / 512 / 4 | `send_pack` / `send_tail` / `send_quiet` | 上行合并参数 |

本地监听地址（`listen`）和日志级别不在链接里，由客户端自己决定。数值越界会被拉回合法范围；格式非法（非数字、非法时长、坏的 base64 等）则**整条链接无效**。

**例子**

最常见的一条（自签证书，只有指纹）：

```
nakis://123e4567-e89b-42d3-a456-426614174000@203.0.113.7:8443?v=1&pin=<64位十六进制>#我的节点
```

域名 + CA 证书（没有 pin，续期不影响客户端）：

```
nakis://123e4567-e89b-42d3-a456-426614174000@vpn.example.org:443?v=1&sni=vpn.example.org#东京
```

明文（仅内网 / 调试）：

```
nakis://123e4567-e89b-42d3-a456-426614174000@10.0.0.2:8443?v=1&tls=0#lan
```

全部参数都用上的一条（IPv6 主地址 + 备用地址 + ECH + 指纹 + 整形等）：

```
nakis://123e4567-e89b-42d3-a456-426614174000@[2001:db8::1]:443?v=1&sni=example.org&pin=abababababababababababababababababababababababababababababababab&ech=AAz-DQAI-__-__vvAQI&alt=198.51.100.4:8443&shape=100-300,400-1200&pool=3-40&age=30s&cc=bbr#%E4%B8%9C%E4%BA%AC%201%20%E5%8F%B7
```

这条链接对应的 `client.json`（节选，其余字段为默认值）：

```json
{
  "server": "[2001:db8::1]:443,198.51.100.4:8443",
  "uuid": "123e4567-e89b-42d3-a456-426614174000",
  "tls": true,
  "sni": "example.org",
  "tls_pins": ["abababababababababababababababababababababababababababababababab"],
  "ech_config": "AAz+DQAI+//+//vvAQI=",
  "shape_up": [[100, 300], [400, 1200]],
  "pool_lo": 3,
  "pool_hi": 40,
  "pool_max_age": "30s",
  "congestion": "bbr"
}
```

### 4.3 订阅

订阅就是一段文本，内容是若干条分享链接，**每行一条**：

- 可以是**明文**（每行一条链接），也可以是对整段明文做的 **base64**（标准或 URL 安全字母表，有无填充、有无换行都行）。判断方法：文本里含有 `nakis://` 就当明文，否则当 base64 解码一次。
- 空行、以 `#` 开头的行、不是 `nakis://` 开头的行都会被忽略（订阅里可以混有别的协议的链接）。
- 某一行无效只会跳过那一行，其余节点照常导入；客户端应告诉用户跳过了哪几行、为什么。
- 节点顺序按出现顺序，名字取各链接的 `#节点名`。
- 服务端脚本生成的订阅是：链接用换行连接并以换行结尾，整体做标准 base64（带填充，不换行）。把它放到任意**HTTPS** 静态网址即可被客户端订阅（内容含 uuid，不要用 HTTP）。托管方如果能设置响应头，常见客户端会识别 `Profile-Update-Interval`（更新间隔，小时）、`Profile-Title`（订阅名）、`Subscription-Userinfo`（流量信息）；这些头**不属于规范**，没有也不影响导入。

### 4.4 链接怎么从服务端配置得出

服务端脚本（以及 `nakis link -s server.json -host 地址`）按这些规则生成：

- 地址：你指定的对外地址（可以有多个，每个一条链接，节点名自动加上地址）；端口默认取 `listen` 的端口，做了端口转发时用对外端口。
- 自签证书：读取 `tls_cert` 的第一个证书，把公钥指纹放进 `pin`。
- **CA 签发、会续期的证书**：不放 `pin`（否则续期后指纹变化，所有客户端失效），`sni` 必须是证书的域名。
- ECH：取 `ech_keys` 的第一条，`config` 前面加上 2 字节长度变成 ECHConfigList，放进 `ech`；此时必须有 `sni`。
- `sni`：显式指定的值，或（地址是域名时）地址本身。
